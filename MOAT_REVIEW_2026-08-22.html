RUDRA Delivery Moat

The brief "compare to Runway Ruby and Topaz, make RUDRA unique and more powerful" sharpened into three questions: where is the structural advantage, where does the architecture leak it, and what code closes the gap this week without a GPU. This report answers all three — and the code shipped with it.

The moat, stated precisely: every competitor starts from already-clipped 8-bit pixels and hallucinates highlights. RUDRA's latent path reconstructs radiance before tone-mapping destroys it, across seven open backbones. But pipeline position is only defensible if the delivery half exists — generate → grade → measure → master without leaving scene-linear. Until today, it didn't. Now it does, and it runs on any machine with numpy.

What shipped — rudra/delivery/, torch-free by design

metadata.py

Dynamic metadata

MaxRGB per-frame analysis, conservative shot detection, per-shot Dolby Vision L1 min/mid/max as 12-bit PQ, HDR10+ scene percentiles, CTA-861.3 statics. Emits dovi_tool generate-JSON, HDR10+ scenes, and a self-describing sidecar in nits + PQ.

exr.py + aces.py

ACES delivery

Dependency-free uncompressed EXR writer/reader; ST 2065-4 container with AP0 chromaticities; matrices derived from primaries + Bradford CAT at runtime, never hardcoded; OCIO v2 config generator with the exact matrices embedded.

controls.py

Artist controls

Global EV, per-region EV over soft masks, log-symmetric luminance qualifiers, highlight desat, hue-preserving shoulder — fixed documented order, JSON-recorded grades, bit-exact replay. itm_strength_map feeds the same masks into SDR2HDRNet as per-pixel recovery strength.

cli.py + bench.py

CLI + benchmark

rudra info / grade / aces / metadata / bench. PU21-PSNR (banding+glare) in pure numpy everywhere; CVVDP JOD when torch + pycvvdp exist — recorded as unavailable otherwise, never silently substituted.

Verification

  • 27/27 new regression tests green in a torch-free sandbox (colorspace, EXR round-trips, metadata schemas, grade order, PU21, benchmark end-to-end, CLI subprocess).
  • EXR output validated with the official OpenEXR bindings: header parses, chromaticities intact, pixel round-trip ≤ 0.05% relative error at half precision.
  • BT.709→AP0 matches the ACES reference matrix to 2×10⁻³; white maps to white in every space pair; round-trip matrices are identity to 10⁻¹⁰.
  • Package import verified with torch absent; model symbols raise a pointed error instead of a stack trace.
  • Not yet exercised: the generated JSON against real dovi_tool / hdr10plus_tool binaries (run once on the GPU box — schema risk is documented in-module), and the CVVDP path of bench.

One-command delivery

# analyze a rendered clip → DoVi L1 + HDR10+ + sidecar
rudra metadata outputs/clip/ --nits-scale 203 --output outputs/clip/master --peak-nits 1000
dovi_tool generate --json outputs/clip/master_dovi_generate.json --rpu-out clip.rpu

# ACES 2065-1 master + OCIO config for Resolve/Nuke
rudra aces outputs/clip/ --output delivery/aces --ocio

# +1 EV push on the 400–2000-nit band, mastered to 1000 nits
rudra grade in.exr --output graded/ --region 400:2000:1.0:0.5 --peak-nits 1000

# Stuttgart/UBC-layout benchmark → publishable PU21-PSNR (+CVVDP on the GPU box)
rudra bench bench_root/ --output results/stuttgart.json

What today deliberately did not touch

The model half is still gated by the 22 Aug post-fix audit, and no delivery code changes that: targets clipped at 10k nits with linear-quantised shadows (pipeline v3 re-ingest), temporal diverging on a two-clip corpus (Stuttgart's 26 videos clear the gate), 0/7 decoder retrains, Stage 3 untrained, the sigma question unsettled. The retrain order in FIXES_2026-08-10.md stands. No quality number gets quoted until post-fix weights exist — the bench harness is how those numbers get produced honestly when they do.
